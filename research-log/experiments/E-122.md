# E-122 — `stress` (superseded)

- **Question:** M17 / §35 mixed workload / UI_SUGGESTION §41: does the adaptive scheduler keep the desktop responsive while browser-like, build-like, file and network work run at once?
- **Hypothesis:** Adaptive keeps the interactive probe near low-latency levels without starving the rest.
- **Host:** Linux 6.6.87.2-microsoft-standard-WSL2 x86_64; AMD Ryzen 5 7520U with Radeon Graphics (Windows 11 -> WSL2 -> QEMU; KVM nested inside WSL2 when accel=kvm)
- **Guest:** FuhrerOS, 4 vCPU offered / 1 used, 4096 MB
- **QEMU:** QEMU emulator version 10.2.1 (Debian 1:10.2.1+ds-1ubuntu3.1), accel KVM; virtio-blk, FFS0 raw image, host cache=writeback; virtio-net, QEMU user-mode (slirp)
- **Kernel:** FuhrerOS 0.1.0 (own kernel), commit `fceac52-dirty`, 2026-09-26T18:05:44Z
- **Workload:** deskstress 10 s x 3 repetitions x 4 policies: HTTP client+server, two CPU-bound build-proxy workers, 8 MiB file copy loop, TCP stream, interactive probe; order rotated.
- **Policy / configuration:** `rootfs/etc/bench/stress.sh` (copy in the run directory)
- **Metrics:** probe dispatch/wake latency, per-component throughput, context switches, thread classes
- **Result:** Adaptive: probe dispatch p50 49,183 µs, file copy 0.06 MB/s (low-latency: 10 µs, 1.18 MB/s).
- **Variance:** see CV% columns in [summary.md](../../experiments/E-122-stress-20260926-1805/summary.md)
- **Interpretation:** Superseded. Exposed F-122 (aging boost never expired). HTTP numbers unreliable (fixed port, connection failures under every policy).
- **Threats:** nested virtualisation (Windows → WSL2 → KVM); one CPU used; few repetitions; synthetic workloads.
