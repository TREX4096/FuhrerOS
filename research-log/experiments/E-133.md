# E-133 — `micro` (final)

- **Question:** NEW_EXPLANATION §35: reproducible CPU, memory, storage, network and desktop micro-benchmarks.
- **Hypothesis:** No hypothesis: a baseline of what the system does.
- **Host:** Linux 6.6.87.2-microsoft-standard-WSL2 x86_64; AMD Ryzen 5 7520U with Radeon Graphics (Windows 11 -> WSL2 -> QEMU; KVM nested inside WSL2 when accel=kvm)
- **Guest:** FuhrerOS, 4 vCPU offered / 1 used, 4096 MB
- **QEMU:** QEMU emulator version 10.2.1 (Debian 1:10.2.1+ds-1ubuntu3.1), accel KVM; virtio-blk, FFS0 raw image, host cache=writeback; virtio-net, QEMU user-mode (slirp)
- **Kernel:** FuhrerOS 0.1.0 (own kernel), commit `4768a1f`, 2026-09-26T18:35:31Z
- **Workload:** fubench cpu/mem/storage/net x3, then fubench desktop once (it starts the compositor).
- **Policy / configuration:** `rootfs/etc/bench/micro.sh` (copy in the run directory)
- **Metrics:** time, rate or latency per benchmark (units in summary.md); NOT RUN where impossible
- **Result:** CPU: prime 62 ms, matrix 10 ms, compilation NOT RUN. Memory: malloc+free 19 ns/pair, memcpy 4,579 MB/s, dependent loads 1.2 / 3.3 / 69.0 / 154.0 ns (16 KiB / 256 KiB / 4 MiB / 32 MiB). Storage: seq write 25.21 MB/s, seq read 370.34 MB/s (cold, read-ahead), random read 5,739 ops/s, random write 4,487 ops/s, 1,402 small files/s created, 12,835/s deleted. Network (own stack, loopback path): TCP 153.53 MB/s, 1-byte RTT p50 2 µs (p99 3), UDP 87,913 delivered packets/s (20000/20000). Desktop: window create 1,666 µs; app launch to window 3-4 ms (terminal, files, editor, browser, settings, Control Center); workspace switch 1,314 µs to the composed frame; composition avg 1,716 µs, max 7,894 µs; terminal keystroke latency NOT RUN.
- **Variance:** see CV% columns in [summary.md](../../experiments/E-133-micro-20260926-1835/summary.md)
- **Interpretation:** A baseline for later work. After F-123, writes are about 14x faster than in E-121 (1.82 -> 25.21 MB/s). Network numbers measure the stack's loopback path, not a NIC. Composition redraws the full 1280x800 screen each frame (about 1.7 ms), which bounds the frame rate far above the 60 fps cap.
- **Threats:** nested virtualisation (Windows → WSL2 → KVM); one CPU used; few repetitions; synthetic workloads.
- **Next experiment:** Terminal latency needs injected input; a second NIC for external throughput.
