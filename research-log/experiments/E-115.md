# E-115 — `transition` (superseded)

- **Question:** RQ4 (NEW_EXPLANATION §36): how quickly does the kernel's classifier follow a change of workload?
- **Hypothesis:** The system class matches each phase within a few profiler windows (< 1 s).
- **Host:** Linux 6.6.87.2-microsoft-standard-WSL2 x86_64; AMD Ryzen 5 7520U with Radeon Graphics (Windows 11 -> WSL2 -> QEMU; KVM nested inside WSL2 when accel=kvm)
- **Guest:** FuhrerOS, 4 vCPU offered / 1 used, 4096 MB
- **QEMU:** QEMU emulator version 10.2.1 (Debian 1:10.2.1+ds-1ubuntu3.1), accel KVM; virtio-blk, FFS0 raw image, host cache=writeback; virtio-net, QEMU user-mode (slirp)
- **Kernel:** FuhrerOS 0.1.0 (own kernel), commit `689bf6c-dirty`, 2026-09-26T16:11:28Z
- **Workload:** transition: phases cpu -> random-io -> sequential-io -> network (loopback TCP) -> interactive, 8 s each, sampled every 250 ms; once under adaptive (sched+cache), once under round_robin+lru.
- **Policy / configuration:** `rootfs/etc/bench/transition.sh` (copy in the run directory)
- **Metrics:** per-sample detected class, confidence, policies, ops; detection delay per phase
- **Result:** Detection 282-397 ms under adaptive, 282-583 ms under round_robin+lru, every phase.
- **Variance:** see CV% columns in [summary.md](../../experiments/E-115-transition-20260926-1611/summary.md)
- **Interpretation:** Superseded only because F-119 changed the adaptive cache.
- **Threats:** nested virtualisation (Windows → WSL2 → KVM); one CPU used; few repetitions; synthetic workloads.
- **Next experiment:** E-119
