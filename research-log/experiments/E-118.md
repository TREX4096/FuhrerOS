# E-118 — `cache` (final)

- **Question:** RQ5: does the adaptive buffer cache improve storage throughput over fixed policies?
- **Hypothesis:** Adaptive matches read-ahead on sequential reads and LRU on re-use workloads.
- **Host:** Linux 6.6.87.2-microsoft-standard-WSL2 x86_64; AMD Ryzen 5 7520U with Radeon Graphics (Windows 11 -> WSL2 -> QEMU; KVM nested inside WSL2 when accel=kvm)
- **Guest:** FuhrerOS, 4 vCPU offered / 1 used, 4096 MB
- **QEMU:** QEMU emulator version 10.2.1 (Debian 1:10.2.1+ds-1ubuntu3.1), accel KVM; virtio-blk, FFS0 raw image, host cache=writeback; virtio-net, QEMU user-mode (slirp)
- **Kernel:** FuhrerOS 0.1.0 (own kernel), commit `e942a12-dirty`, 2026-09-26T16:27:33Z
- **Workload:** iobench on a 64 MiB file through a 1024-block (4 MiB) cache: seq, random, hotset (80 % in 2 MiB), scan (hotset + sequential scan). 6 s per run, 2 repetitions, reversed order in the second.
- **Policy / configuration:** `rootfs/etc/bench/cache.sh` (copy in the run directory)
- **Metrics:** MB/s, hit rate, read latency p99, cache CPU, read-ahead issued/used
- **Result:** Sequential (MB/s): LRU 19.67, FIFO 20.28, CLOCK 20.25, readahead 321.13, adaptive 311.58; hit rate LRU 745, readahead 999, adaptive 999 per mille; read p99 LRU 499 µs, adaptive 74 µs. Random: 19.92-21.02 for all. Hotset: LRU 75.32, FIFO 56.62, CLOCK 78.96, readahead 65.12, adaptive 61.55. Scan: 25.90-29.18. Cache CPU per read: 338-938 ns except sequential readahead/adaptive (7,814 / 8,060 ns, which includes issuing prefetches).
- **Variance:** see CV% columns in [summary.md](../../experiments/E-118-cache-20260926-1627/summary.md)
- **Interpretation:** RQ5: partly yes. The adaptive cache detects the sequential stream and matches the dedicated read-ahead policy (97 % of its throughput, 15.8x LRU), it is the best policy on random (21.02 MB/s) and within 8 % of the best on scan (26.87 vs 29.18). It is 18 % below LRU and 22 % below CLOCK on the hotset workload, so on re-use workloads it does not pick the best fixed policy. Hotset results vary between runs (LRU 75.32 here vs 87.82 in E-114) and there are only 2 repetitions. No extra memory: all policies use the same 1024 blocks.
- **Threats:** nested virtualisation (Windows → WSL2 → KVM); one CPU used; few repetitions; synthetic workloads.
- **Next experiment:** Investigate the hotset loss (adaptive uses CLOCK only when io_class is RANDOM and hits exceed misses/2); more repetitions.
