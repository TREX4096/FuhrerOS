# E-132 — `ablation` (final)

- **Question:** RQ1/RQ3 and NEW_EXPLANATION §38: which parts of the adaptive scheduler produce its effect, and how sensitive is it to window and hysteresis?
- **Hypothesis:** Latency gains need both profiling and class-based parameters; longer windows / more hysteresis react slower and raise tail latency.
- **Host:** Linux 6.6.87.2-microsoft-standard-WSL2 x86_64; AMD Ryzen 5 7520U with Radeon Graphics (Windows 11 -> WSL2 -> QEMU; KVM nested inside WSL2 when accel=kvm)
- **Guest:** FuhrerOS, 4 vCPU offered / 1 used, 4096 MB
- **QEMU:** QEMU emulator version 10.2.1 (Debian 1:10.2.1+ds-1ubuntu3.1), accel KVM; virtio-blk, FFS0 raw image, host cache=writeback; virtio-net, QEMU user-mode (slirp)
- **Kernel:** FuhrerOS 0.1.0 (own kernel), commit `4768a1f`, 2026-09-26T18:30:24Z
- **Workload:** schedbench mixed scenario, 3 repetitions per variant: A1 priority policy (controller off), A2 adaptive with profiling off, A3 round-robin with profiling on, A4 adaptive, A5 adaptive + adaptive cache (from E-120), A6 window 25/500 ms, A7 hysteresis 1/5.
- **Policy / configuration:** `rootfs/etc/bench/ablation.sh` (copy in the run directory)
- **Metrics:** as for sched
- **Result:** Mixed scenario, median of 3, cache LRU except A5. Dispatch p50 / p99 (µs): A1 controller off 29,067 / 29,261; A2 profiling off 11,095 / 18,019; A3 profiling on, no switching 29,066 / 29,378; A4 adaptive 7 / 92; A5 adaptive + adaptive cache 7 / 272; A6 window 25 ms 7 / 100; A6 window 500 ms 7 / 13,091; A7 hysteresis 1 7 / 76; A7 hysteresis 5 7 / 10,966. Batch jobs/s (x100) 914,110 (A5) to 975,074. Policy decision time A1 27,853 ns/s, A4 138,345, A5 265,819. Profiler total for the whole boot 8.85 ms.
- **Variance:** see CV% columns in [summary.md](../../experiments/E-132-ablation-20260926-1830/summary.md)
- **Interpretation:** RQ1/RQ3: the gain needs both profiling and class-based parameters (A2, A3 vs A4). Slower reaction (500 ms window or hysteresis 5) raises dispatch p99 about 120-140x because new threads wait unclassified; 25 ms vs 100 ms makes no measurable difference. A5 (adaptive cache added) has a higher tail (272 µs, CV 118 %) and 4.8 % less batch throughput than A4 in this run; with 3 repetitions and this variance the difference is not established. Overhead: profiler < 0.004 % of CPU over at least 270 s of benchmarks; policy decisions 0.14 ms/s under A4.
- **Threats:** nested virtualisation (Windows → WSL2 → KVM); one CPU used; few repetitions; synthetic workloads.
- **Next experiment:** More repetitions for A4 vs A5.
