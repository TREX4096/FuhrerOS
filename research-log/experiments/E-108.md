# E-108 — `ablation` (superseded)

- **Question:** RQ1/RQ3 and NEW_EXPLANATION §38: which parts of the adaptive scheduler produce its effect, and how sensitive is it to window and hysteresis?
- **Hypothesis:** Latency gains need both profiling and class-based parameters; longer windows / more hysteresis react slower and raise tail latency.
- **Host:** Linux 6.6.87.2-microsoft-standard-WSL2 x86_64; AMD Ryzen 5 7520U with Radeon Graphics (Windows 11 -> WSL2 -> QEMU; KVM nested inside WSL2 when accel=kvm)
- **Guest:** FuhrerOS, 4 vCPU offered / 1 used, 4096 MB
- **QEMU:** QEMU emulator version 10.2.1 (Debian 1:10.2.1+ds-1ubuntu3.1), accel KVM; virtio-blk, FFS0 raw image, host cache=writeback; virtio-net, QEMU user-mode (slirp)
- **Kernel:** FuhrerOS 0.1.0 (own kernel), commit `ba10d0c-dirty`, 2026-09-26T15:28:42Z
- **Workload:** schedbench mixed scenario, 3 repetitions per variant: A1 priority policy (controller off), A2 adaptive with profiling off, A3 round-robin with profiling on, A4 adaptive, A5 adaptive + adaptive cache (from E-117), A6 window 25/500 ms, A7 hysteresis 1/5.
- **Policy / configuration:** `rootfs/etc/bench/ablation.sh` (copy in the run directory)
- **Metrics:** as for sched
- **Result:** A4 wake p50 975 µs (E-105 had 44 µs for the same configuration); A6-window500 and A7-hyst5 had much higher p99 (16,001 / 13,995 µs) than window25 / hyst1 (1,381 / 1,075 µs).
- **Variance:** see CV% columns in [summary.md](../../experiments/E-108-ablation-20260926-1528/summary.md)
- **Interpretation:** Superseded. Ran on the pre-F-115/F-116 binary while those fixes were already in the working tree (the config says `-dirty`, but the ISO was built before the edits). Exposed F-117.
- **Threats:** nested virtualisation (Windows → WSL2 → KVM); one CPU used; few repetitions; synthetic workloads.
