# E-004 — workload transitions with the revised map

**Directory:** `experiments/E-004-transition-20260926-1058/` (Graph 3: graph3-adaptation.svg)
**Question:** RQ4, with D-006 rev. 2. How fast does fuhrerd follow phase changes, and what
does the reaction time cost?
**Setup:** bench VM, KVM nested in WSL2. The phases are idle, cpu, randread (4 KiB qd32), seqread (1 MiB qd8) and idle, 10 s each. Caches were dropped once before the run. Configurations were shuffled; reps=3.

## Results (per rep)

| config | switches | randread: time to SPECIALIZED | randread MB/s | seqread MB/s |
|---|---|---|---|---|
| static normal | 0 | — | 3.2 / 3.3 / 3.5 | 143 / 167 / 104 |
| static batched | 0 | — | 31.0 / 33.5 / 34.7 | 206 / 162 / 152 |
| static specialized | 0 | (from start) | 26.0 / 34.0 / 37.8 | 569 / 564 / 587 |
| **adaptive** | 3 / 3 / 2 | 4.0 / 3.0 / 4.0 s | 25.2 / 21.4 / 23.9 | 552 / 523 / 585 |

## Interpretation
- Adaptive reaches the mapped policy **3–4 s** after the random phase starts. It stays
  SPECIALIZED into the sequential phase, where the revised map wants the same policy, so no switch is needed.
  In E-002 (old map) this phase cost an extra switch and ran at 400–424 MB/s; now it runs at 523–585,
  equal to static SPECIALIZED.
- The price of hysteresis is visible: in a 10 s random phase adaptive loses about 25–35 % against
  static SPECIALIZED, because it spends 3–4 s under NORMAL. With longer phases (the desktop
  time scale the design targets) this cost shrinks proportionally. With shorter ones,
  E-002's ablation shows interval 100 ms or hysteresis 1 halves it.
- The number of switches fell from 4–5 (E-002) to 2–3: the revised map has fewer distinct targets.

**Threats:** as E-002. The phases are short relative to the reaction time by construction.
