# E-001 — pipeline validation (quick main suite)

**Question:** Does the experiment pipeline produce complete, analysable results?
**Hypothesis:** n/a (infrastructure run; 1 repetition — not evidence for H1–H4).
**Setup:** bench VM (4 vCPU, 4 GB, 40 GB), KVM nested in WSL2, kernel 6.12.111-0-virt,
QEMU 10.2.1; workloads randread, seqread, cpu, netlat; 5 s runs, 4 s warm-up; reps=1.
**Result:** see `experiments/E-001-main-20260926-0630/summary.md`. Every configuration
produced JSON; the report and graphs were generated.
**Observations worth testing properly (not conclusions):**
- randread: normal 1,041 IOPS vs batched 9,087 vs specialized 14,529 — the libfuhrer
  asynchronous backends keep 32 requests in flight, the synchronous backend 1. The gain is
  therefore at least partly an application-interface effect, not a kernel-policy effect.
  → added A6 decomposition (knobs-only vs lib-only) to the main suite.
- seqread: specialized (O_DIRECT) 658 MB/s vs batched 50 MB/s — contradicts H2 as far as
  Fuhrer-aware I/O is concerned.
- cpu: B0 1,114 vs ~1,750 Mops/s for the others, from a different boot; with n=1 this is
  indistinguishable from host noise (cpu stdev within a run up to 250).
**Threats:** n=1; nested virtualisation.
**Next experiment:** E-002 (all suites, reps=3, time=10 s).
